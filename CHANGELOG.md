## [0.1.0] - 2026-09-12

- A turn that under-declared its own scope no longer stops to ask (harness). The scope of a turn always has an upper bound the model did not author — the approved plan step, or the ceiling Rust freezes. What the model then declares inside that bound is its own bookkeeping, so a refusal the ceiling would not have raised is not a decision for the engineer: the model is told which ops its `turn.begin` is missing and re-declares (`TURN_ENVELOPE_TOO_NARROW`), or, under Auto, the turn envelope is widened to the ceiling for exactly that op and the call proceeds. Anything genuinely outside the ceiling still raises the same approval card. The 2026-09-06 golden run raised two such cards: `ldo_3v3` asked for `route_net` on a ceiling that allows every op, and `power_subsheet` asked to create the very sheet file the user's message had named.
- A structural entry is a verb and, optionally, the file it acts on. The ceiling always writes the file (`create_sheet:power.kicad_sch`); a model usually writes the bare verb, because the file is already in `sheets` and in the user's own sentence. The bare verb is now satisfied by the ceiling's own entry and rewritten to it, and file spellings are compared by stem, as everywhere else. The session ceiling also stops holding the caller's sheet array: extending it in place had been landing in the project's sheet list, so the "does this file exist yet?" test answered yes and the entry that makes a new sheet legal was never added.
- P9 no longer refuses `ops.validate` for a style rule it has already raised. Validating is how the model checks its own work and it writes nothing — the escalation belongs on `sch.plan`, the last call before a write, and stays there. An injection lets the call through, so the model reads back the engine's own "ok, no warnings" and re-validates the same list; the golden `ldo_3v3` turn was refused one call later for "violating again", went looking for another way to connect two pins, and landed on the op its own declaration had not listed.
- A sheet-scoped check returns findings again (engine, P0): `check.{integrity,style,layout,erc,power,nets,pinmap}` with a `sheet` argument resolved the selector to the uuid instance path (`/234b.../d030...`) and compared it against `Finding.sheet`, which is the instance *names* path (`/power/`), so the filter matched nothing and every sheet-scoped check answered `[]`. That hid every style, layout and integrity finding from the Lead's post-apply passes - the stylist and the Fixer have been running on empty lists in all runs so far. One shared filter now serves every family and compares in the form the finding carries: the project-relative `file` first (one-to-one with the requested file even when a sheet is instantiated twice), falling back to the instance path or names path; a finding with neither is project-wide and is kept. All three ways of naming a sheet (file, `/child/`, uuid path) select the same findings.
- Routes are drawn around foreign pins (engine): `route_net` was obstacle-free geometry - "auto" turned its corner at `(b.x, a.y)` - and in run 20 that corner landed on J1.3's tip while the leg ran on up J1's pin column, wiring three of the connector's pins into the rail, one of them under a no-connect. The route now tries the other leg order and then a Z with its jog on a free 50 mil grid line (nearest the middle first) before it draws; when nothing is clear it draws the authored shape anyway and names what it crosses in the new `ROUTE_THROUGH_PIN` warning, never silently. `add_no_connect` on a pin a wire already ends on (or a junction, label or stacked pin) is refused as `NO_CONNECT_ON_CONNECTED_PIN` with the way out, and a wire drawn onto an existing marker warns `WIRE_ON_NO_CONNECT` - the marker was written first, so there is nothing left to refuse.
- A power symbol placed as a part is annotated as a port (engine): a model drawing designators from its refdes lease wrote `power:PWR_FLAG` as `PWR1`, which put a port in the BOM and made the delivery check ask it for a footprint (`FOOTPRINT_MISSING`, run 20). `place_component` now puts the reference back on KiCad's convention - `#FLG` for a `PWR_FLAG`, `#PWR` for any other port, one free number per instance path - and reports the rename as `PLACEMENT_POWER_DESIGNATOR`; an authored `#` name is kept. The delivery gate reads what the symbol is (the library's `(power)` flag, the `power:` library, the `#` convention) rather than the reference alone, so files already written with the old name are covered too.
- `SHEET_NO_PINS` no longer fires on a hierarchy whose blocks meet on the rails (engine): a power sheet whose whole interface is VBUS_5V in, +3V3 out and GND needs no sheet pin, because power ports and global labels merge across a sheet boundary on their own. The rule is suppressed when the child carries rails and nothing else crosses; a hierarchical label (which is only connected through a sheet pin of the same name) or a local label the parent also carries still reports the scaffold.
- Power symbols are ports whichever op writes them (engine): `place_component` used to treat `power:*` like an ordinary part - it drew the `#PWR`/`#FLG` reference KiCad hides and honoured the rotation the model wrote, so a real run stood a `PWR_FLAG` at 90 degrees across four of a connector's pins with "#FLG1" printed beside it. A power symbol now hides its Reference (new `inv_` test: every `power:*` instance in a written file carries `(hide yes)` on it, whichever op wrote it), takes its pose from the pin it lands on - a GND bar down, a rail arrow up, a `PWR_FLAG` along the pin - or the library's upright pose in free space, and reports the ignored rotation as `PLACEMENT_POWER_ROTATION_IGNORED`. `exact: true` keeps an authored pose. A power symbol standing on a pin is no longer nudged: it is connected by design.
- A power port's value text now draws horizontally at every rotation (engine): the writer stored field angle 0 whatever the port's own rotation was, and KiCad composes the two, so a port turned a quarter turn drew its net name sideways - down a connector's pin row, and through its own glyph. The stored angle cancels the rotation exactly as `autoplace` does for every other symbol, and the offset follows the port's body axis read off the glyph rather than always +/-y (past the glyph plus half the text's own run when that axis is horizontal, so the name is not drawn over the arrow). Unrotated ports are byte-identical.
- Power ports and `PWR_FLAG`s never land silently (engine): when nothing along the leg was clear the port was written on top of its neighbour with no warning at all (a run put a `+3V3` on a capacitor's `10uF`). The search now also steps up to 200 mil to either side of the leg - the L that `route` draws, once there is a leg to turn off - takes a neighbour's property text into account when the text, not the symbol anchor, is what reaches the candidate, and keeps one grid square of reading gap from any text it shares a row with: touching boxes are not an overlap but "+3V3 PWR_FLAG +3V3" still reads as one string, which is what 3 of the 13 golden sheets drew. When nothing clears, the new `PORT_STUB_BLOCKED` warning names it and the layout check reports the overlap. A `PWR_FLAG` hung beside a port puts its own text on the far side from that port's text.
- Fields the engine placed are placed again when they stop fitting (engine): `set_component_parameters` re-runs the autoplace when it changes a Value or a Reference, and `move_component` / `set_component_transform` do the same - a turn moved the body out from under the texts and left them lying across it, which is `FIELD_OVER_OWN_BODY` with no op that could repair it. Only symbols marked `(fields_autoplaced yes)` are touched; fields a human or another tool anchored keep their bytes (red line 2), so the golden `edit_existing_value` fixture, whose author parked R1's Value on the symbol origin, still reads "2k2" exactly where it was written.
- Layout audit, second pass (engine). `LABEL_OVER_WIRE` used to need the label's anchor to *be* a wire endpoint with the wire leaving in the reading direction, so it saw 3 of the ~14 net names a wire is actually drawn through; it now also tests the text box against every wire and bus on the sheet (the label's own stub exempt within 50 mil) and covers a power port's Value, which is a net name on the page but not a `label` object and which no rule in the family had ever looked at. A label written *beside* the wire it names — the mid-span label, the ordinary way to name a net — still passes, because the box is shrunk by a pen width first.
- `TEXT_OVERLAP` compared a field only with a neighbour's *graphics*, so a vertical `PWR_FLAG` printed straight down a connector's four pin leads was silent. It now also tests the neighbour's pin leads (reconstructed tip-to-body, not the bounding rectangle, so the blank corners of a capacitor's box stay blank), and the `#PWR*` convention exemption is narrowed to the pin the port actually shares: a flag hung on pin 4 is not licensed to write its name across pins 1 to 3.
- `ROW_MISALIGNED` was a false-positive generator on a 50 mil grid — it compared bounding-box bottoms of any two parts of at most 8 pins within 800 mil, so run 19 reported a regulator against a capacitor 700 mil away and 200 mil lower. It now requires the same pin count, the same rotation and mirror, pins that all sit on one line, pin tips rather than box bottoms, nothing drawn between the two along the row, and an offset that is not a whole 100 mil placement step. Zero findings across all twelve golden references, asserted by a replay test.
- New: `PAGE_UNDERUSED` (Info) for a sheet whose whole drawing fills under a tenth of the drawing border and sits well off the middle of it — 12 of 12 golden sheets did, at 0.5 % to 2.9 % of an A4 page. Never fixed automatically: spreading the blocks out or choosing smaller paper is the author's call.
- New: `LABEL_PAIR_SHOULD_BE_WIRE` (Info) for one net name written twice within 500 mil with no symbol body in between, where a line is the drafting norm.
- New hierarchy-scaffold rules (Warnings, delivery family): `SHEET_NO_PINS` for a sheet symbol with no pins in front of a child that has a circuit on it — nothing crosses the boundary, and neither `SHEET_PIN_UNMATCHED` nor `HIER_LABEL_UNMATCHED` has anything to compare — and `SHEET_CHILD_EMPTY` for a child file with nothing drawn on it at all.
- ERC parity gap closed: an unwired hierarchical sheet pin is `SHEET_PIN_UNWIRED` (Error), which is what `kicad-cli sch erc` has always reported as `pin_not_connected`; `PINMAP_UNCONNECTED` only ever walked symbol pins, so the engine was two errors short of KiCad on the `power_subsheet` golden.
- `TITLE_BLOCK_EMPTY` is a Warning, not an Info: the harness fills the title block itself on a new project, so one still empty at check time got that way afterwards and a reader sees it on the plot.
- Findings carry machine-readable `evidence` beside the English message, so a mechanical repair can name its target instead of parsing a sentence: `DECAP_FAR` gives `nearest_pin` / `nearest_pin_at_mil`, `ROW_MISALIGNED` gives `target_y_mil` (or `target_x_mil`) and a signed `delta_mil`, `TEXT_OVERLAP` and `FIELD_OVER_FIELD` give the `blocker` and the `axis` with less to clear. Facts only; the verdict stays the engine's (red line 6) and a caller that ignores the map sees the finding it saw before.

- Drawing border (engine): the placement nudge and the layout gate now read one definition of where the page ends (`gates::drawing_border`: 500 mil in from the left, right and top edges, 1500 mil at the bottom for the title block). The nudge used to return "clear" for any empty spot before it looked at the frame, so a real Build run wrote an AMS1117 at (0, 100) mil - alone at the paper corner, under the worksheet frame, outside the block holding its own capacitors. An empty spot outside the border is no longer clear: it goes through the same ring search, which only ever offers in-frame candidates, and is refused with `PLACEMENT_BLOCKED` naming the border rectangle when the border is further away than the 600 mil nudge bound. `exact: true` still writes the authored position verbatim and reports the new `PLACEMENT_OFF_FRAME` warning instead of refusing.
- `OUT_OF_FRAME` can fire at last: it tested the paper rectangle, which nothing on the page can leave, so it never reported anything. It now tests symbol bodies, label text and wires against the same drawing border - a Warning off the border (the object is on the page but under the frame or the title block; it does not refuse a write), the existing Error when the anchor is off the paper or the body has nothing on it at all.
- Rail ports draw the rail they name: `place_vcc` / `place_gnd` without a `lib_id` defaulted to `power:VCC` (or `power:GND`) whatever the net was, so a run drew four VCC glyphs on a VBUS rail although `power:VBUS` exists. The glyph now follows the net name through the one borrow rule (`power_glyph`), which also learned to borrow by voltage: a rail carrying a stock rail's name as a whole token takes that glyph (`USB_5V` -> `power:+5V`, `VDD_3V3` -> `power:+3V3`, `-12V_FAN` -> `power:-12V`), ground-class names take `power:GND`, anything else keeps `power:VCC` / `power:VEE`. A borrowed glyph is reported as `OPLIST_RAIL_GLYPH_BORROWED`; the real name still travels in the symbol's Value, which is the name KiCad reads the net from, so netlists do not move. Macro rail parameters share the rule.
- Nothing a step does fails in silence: a step whose one-shot `ENVELOPE_SHEET_UNDECLARED` redraw also fails is carded under Review and recorded as an auto decision under Auto (it used to claim it had already been carded and disappear into a skip); a Rust envelope refusal on the harness path raises the same scope card the model path raises; `system.auto_step_skipped` is emitted once per skip; a step that wrote nothing says so; and a plan pause now carries its own card with the reason, not only a status line.
- Hook and dispatch judge the same op-list: the Lead normalises a call before P0-P12 exactly as the registry does on the way in, so the engine's own sheet spellings (`/` for the root, the instance path `/power/`) are routed to their files instead of being refused as a `scope_widen` hard stop, and an op-list `sheets` map is checked against the envelope like the array form.
- Plan preconditions (F3): before a Drafter is dispatched, every file the step's envelope names must exist (the engine summary is the source). A file the plan declares is created first - the repair runs under the plan's own `create_sheet` entries, so a draft step's envelope no longer turns it into a structural hard stop - and a file the plan does not declare pauses the plan on that step. Two consecutive skips for the same reason also pause.
- Errors that self-correct in one retry: `ops.template` canonicalises its op name (plus aliases for the spellings real runs used), six error sites carry remediation (paths localised to the project, `OP_UNKNOWN` with the nearest ops and the vocabulary, `ENVELOPE_OP` with `allowed_ops`, `SHEET_UNKNOWN` with the project's sheets, an empty match as `OBJECT_NOT_FOUND`), and P2 envelope denials hand the model the compact envelope it has to fit inside.
- Prompt-cache fidelity (F5): history keeps the exact tool-result blocks that were sent (it used to store a local `AgentToolResult` the provider never saw, killing the prefix after a turn's first tool call); a subagent's corrective retry replays pi's own messages verbatim; OpenAI-compatible calls carry a stable per-role, per-session `prompt_cache_key`; the Anthropic layout is A (end of system, covering the tool table) / B (plan snapshot, 1 h) / C (last turn end) / D (the tail of the payload being sent), with B no longer downgraded to 5 minutes when the plan snapshot is also the last message; the compaction side-call gets its own cache shard and none of the Lead's breakpoints.
- Drafter contract (F4): `sch.dryrun_scratch` returns the digest of the op-list it checked, and a final answer matching no accepted dry run costs one corrective round instead of a failed apply. `ops.validate` and `sch.dryrun_scratch` also carry advisory `ENVELOPE_*` warnings naming the approved sheets.
- Plan acceptance the harness restated from the plan's own parts and nets (`component_count`, `net_has_pins`) is advisory: it is evaluated and shown with its label and the engine's evidence, but only rows the Architect wrote can pass or fail a plan - a threshold the harness authored is not the engine's judgement of a circuit (red line 6).
- Card answers that arrive before the tool registers its waiter are kept (run 16 stalled on an `ask_user` card answered in the same tick).
- Canvas gestures: new setting `canvas.drag_selects` (default off) makes a left drag on empty space rubber-band like eeschema instead of panning; middle-drag no longer trips the WebView2 autoscroll widget; ctrl+wheel takes one detent per notch; Mod+Home fits once.
- Text metrics (engine): every text is measured through a per-character advance table read off KiCad 10's own stroke font (`sch_read::bbox::text_width_mil`) instead of `chars x 0.8 x size`, which was 30% short on `WWWWW`, 46% short on a CJK value and 15% over on `iiiii`. One function now serves the layout gate, the placement nudge, the power-port and `PWR_FLAG` clearance searches and the text boxes the canvas draws, so overlap verdicts and canvas boxes move for existing sheets (file bytes untouched; a symbol whose library anchors are only clear under the old metric is field-autoplaced when newly written). "PWR_FLAG" measures 377 mil at the 50 mil field size, not the 320 mil the escape's ceiling was written for. `sch-read/tests/text_metrics.rs` re-measures the model against `kicad-cli sch export svg` (15 strings x 3 sizes, within 5%) under `FLUXSMITH_CONFORMANCE=required`.
- `symbol_text_boxes` resolves field justification through the symbol transform (eeschema's `SCH_FIELD::GetBoundingBox` composes the stored angle and justification with the symbol's rotation and mirror), so `gates::overlap` verdicts and canvas text boxes change for pre-existing mirrored / 180-degree symbols. File bytes untouched.
- Fixes (engine): a `PWR_FLAG` whose cached library symbol carries no graphics was hung a fixed 100 mil to the side with no obstacle test at all, onto a neighbouring pin or wire end if one was there (which merges two nets); that branch now runs the same connection-point filter as the rest of the search. A `.kicad_sch` that exists but cannot be opened keeps "check the file permissions" instead of being told to run the scaffold step, which recreates nothing and fails again on the next read.

- Power-port drafting (engine): a `PWR_FLAG` that cannot stand on its own pin now runs the same clearance search as the port stub instead of stepping a fixed 100 mil against connection points only - it printed "PWR_FLAG" straight over the rail port's own text on 7 of the 13 golden sheets ("PWR_FLAGND", "PSWR3_FLAG"). A power port on a sideways pin turns a corner (100 mil out along the pin, then 100 mil down for a ground / up for a rail) instead of hanging off the end of a 200 mil rail stub in the pin's own row, where on a connector it sat level with the neighbouring pins' labels; `move_component` follows both legs of that L when it carries the port along.
- Text collisions are detected at last (KiCad's ERC has no geometric text rule, so nothing else can see them): `FIELD_OVER_OWN_BODY`, `FIELD_OVER_FIELD` and `LABEL_OVER_WIRE` join `TEXT_OVERLAP` in the layout family, over every *visible* field rather than Reference/Value alone, and the blanket `#PWR*` exemption is narrowed to what KiCad's convention actually covers — a power port's value may sit on the pin and body it feeds, never on its own glyph, another symbol's field or a label. All warnings; nothing new refuses a write.
- Empty title blocks are filled for real. The skill has promised "the system fills an empty title block from the sheet name after the turn" since 0.5; the plan-driven path called the post-turn gate without the repair context, so it never ran and 14 of 14 golden sheets shipped untitled. The fill now runs on every writing turn, on each sheet file that turn wrote whose `TITLE_BLOCK_EMPTY` the engine reports, inside the same turn checkpoint and through the normal apply path.
- Hierarchy scaffold: the child's hierarchical labels get one row counter per column, so an input and the output it feeds share a row instead of a staircase, and the slot corridor is sized from the pin count. On the parent, `add_sheet` pins are distributed at 100 mil pitch centred on each edge and the symbol is sized from its pin count when `size` is omitted (`size` is now optional).
- opspec v1 (additive, `protocol_version` unchanged): `place_decoupling` takes `near: "U1.3"` and anchors the capacitor beyond that pin, on the axis the pin points away from its own body; the new `DECAP_FAR` warning reports a 100 nF - 10 uF capacitor on a rail drawn more than 500 mil from every power pin on it. `place_led_indicator` no longer mints a `<net>_LED` name for the node between the resistor and the LED — it draws the wire and leaves the node unnamed unless `mid_net` says otherwise.
- Placement (engine, additive to opspec v1): `no_nudge` is an authorable common field - it keeps the position you wrote and still snaps it to the 50 mil connection grid, so a designed layout no longer has to reach for `exact`. `exact` keeps the position verbatim as before but now reports `PLACEMENT_OFF_GRID` (naming the offending pins) instead of writing off-grid in silence, `Place::Relative` off an off-grid anchor included. The nudge ring search stops at 600 mil: a spot with nothing free within that is refused per op with `PLACEMENT_BLOCKED` naming the blocker, rather than teleporting the part across the sheet (a real run moved a diode 2600 mil away from its resistor).
- opspec v1 (additive, `protocol_version` unchanged): `place_array` wires its own elements (`pin1_labels` / `pin2_labels`, alias `pin1_nets` / `pin2_nets`, one net name per element; `pin1_rail` / `pin2_rail` for one rail on every element as a power port; `pinN_scope`), with the pitch clamped to 700 mil when the array marches along the pin axis. A field no op branch reads is no longer dropped in silence: the parser reports `OPLIST_UNKNOWN_FIELD` in `ops.validate` / `ops.expand` and in the per-op warnings of `sch.plan` / `sch.apply`.
- Golden set as the abort-line gauge (2026-08-30/31): built-in rate table fallback (estimated rates, major-version fallback), `pnpm golden:run --n 3` statistics (pass/N, card median/p90, hard stops, weights, nightly subset) and a `golden-nightly` CI job; oracle matches only task-named nets by name, connectors by pin count, LED/connector values as wildcards. Harness: `allowed_ops` closed under macro expansion and the power-port family, macro names never scope, sheet name/file matched by stem, human-named `*.kicad_sch` files extend the session ceiling and the declaration, free-text structural entries canonicalised. Engine: a PWR_FLAG on an occupied pin hangs beside it on a stub at a verified free point, flag/rail proximity is not SYMBOL_OVERLAP. Result: 10 tasks x 3 all pass, hard stops 21 -> 11 -> 0 on the affected tasks, ERC errors only where inherent to the task.
- Crash recovery (Phase B), M3 tools (`web.fetch`, `docs.pdf_text`, `facts.write`, `parts.bom`, `parts.decision` card), workflow runner for non-verify flows with `trust_workflows` consent, L5 replay / L6 injection corpus / cache-invariant tests, engine `inv_`/`reg_` tests, fuzz targets, conformance gate, opspec schema drift check; `.fluxsmith/.gitignore` now ignores the whole directory with the D-36 whitelist (legacy three-line files upgraded in place).

- UI/copy (Phase F): three-part error copy (`error.<CODE>.{title,why,next}`, 92 codes, four languages, enforced by tests) used by the stream error block and toasts; hard-stop cards split into a system zone and an agent zone with a per-session "don't ask again for this condition" checkbox (OQ-17); rollback dialog lists the turns that will be undone, blocks on locks / pruned checkpoints and explains the pre-rollback snapshot; intake card for multi-file / folder / `.pretty/` drops with per-file actions from `intake_defaults`; skill editor (front matter + body + L0 preview + pack golden tests replayed through the engine); message-stream windowing for long sessions, sheet thumbnails (LRU); OS clipboard image paste fallback (arboard); structured JSONL logs with 20 MB / 10 files / 14 days rotation and a leak-regression corpus; local update check (release folder / git tag) and first-run bytes-affecting disclosure; About licences corrected; design-system lint (`pnpm lint:design`) and token contrast tests; one-time tips for the first decision card / summary / compaction; cloud-sync folder detection (notice + 1 s watcher debounce); Windows WebView2 native dialog with four-language strings and long-path prefix helper; unplaced multi-unit list in the parts panel; staged reveal disabled above 2000 objects.

## Design phase (2026-08-25 to 2026-08-27)

Before the first implementation milestone the project was a set of specifications rather than code,
and its changelog was a running log of design decisions in the author's working language. Those
entries pointed almost entirely at design documents that are kept outside version control, so they
are summarised here instead of reproduced. The decisions themselves are recorded in `CLAUDE.md`, in
`SECURITY.md` and in the git history.

What was settled in that period, in the order it happened:

- **The engine is fluxsmith's own.** Rather than shelling out to an existing tool, the project
  builds a Rust-native KiCad schematic engine with its own op vocabulary and its own frozen UUIDv5
  seed rules, verified against KiCad itself rather than against another implementation. The
  engine architecture, its invariants and the KiCad-parity criteria date from here.
- **The interaction model became AI-led.** Plan, Build and Review modes; a `DesignPlan` envelope; a
  turn as a transaction with a checkpoint and whole-turn rollback; a Lead agent with subagents; a
  frozen hard-stop list; and policy hooks as code rather than prompt text. Direct manipulation, a
  proposal queue and per-op undo were all removed.
- **The authorisation model moved into Rust.** BuildSession tokens, single-use grants bound to a
  consent event, the envelope and its counters re-checked on the Rust side, and the rule that the
  scope of a turn always has an upper bound the model did not author.
- **The app shape.** A single instance with multiple project tabs; SQLite for app data; a four-layer
  storage split for external and generated files; KiCad 10 as a user-installed runtime prerequisite
  with an environment gate; the project lifecycle; and the approval-policy axis (Ask, Review, Auto).
- **The harness.** After surveying existing agent frameworks, the loop was built on `pi-ai` and
  `pi-agent-core` bundled directly into the webview — a feasibility spike confirmed it runs without
  a Node runtime — with the Rust enforcement points and the red lines unchanged either way.
- **Parts sourcing and datasheet facts** were scoped as a later milestone, with a sourcing agent and
  a facts agent, and the rule that a conversion result is a claim to be checked against the
  datasheet rather than a fact.
- **The visual system.** No emoji anywhere in the UI, Lucide icons, a black-and-white-and-grey token
  system with semantic colour reserved for state, light and dark themes through tokens only, and
  four interface languages.
- **Licensing** moved to Apache-2.0 with a `NOTICE`, and a dependency policy of Apache-2.0, MIT and
  BSD-class only, with GPL tools invoked as separate user-installed processes.
- **Documents left version control.** Specifications, research notes and review records are kept
  locally, and the README became English with three translations.

The first implementation landed on 2026-08-27: nine engine crates plus `fluxsmith-cli`, passing
byte-exact round-trips, netlist parity with `kicad-cli`, post-write ERC and double-apply idempotence,
with a ten-task golden set; and the Tauri effect kernel plus the webview harness — typed IPC,
BuildSession and grants, checkpoints and rollback, SQLite, the secret store, streaming `net_fetch`,
the environment check, the watcher, skills, the symbol index, the policy hooks,
the tool manifest, and the Lead with its subagents.

- Repo scaffold: directory layout, `CLAUDE.md`, `SECURITY.md`, `LICENSE`. No implementation yet.
