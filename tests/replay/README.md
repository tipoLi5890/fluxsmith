# Replay recordings (L5)

`*.jsonl` / `*.jsonl.gz` — one JSON entry per line, consumed by `pnpm replay` (which runs
`src/agent/__tests__/replay.test.ts` with `FLUXSMITH_REPLAY_FILES` set).

| entry | fields | meaning |
|---|---|---|
| `meta` | `version, session_id, project, turns[{turn,text}], source` | the user messages that drive the replay; `source: seam` = strict (context hashes checked), `history` = lenient (role order only) |
| `model` | `call_index, role, model, context_hash, assistant` | one model call; `context_hash` = sha256 over (system, tools, messages) the loop was about to send, `assistant` = the final pi `AssistantMessage` (no deltas) |
| `ipc` | `call_index, name, args_hash, result, error` | one IPC call and its outcome (fake IPC or the in-app `setIpcTap`); matched by name + args hash, otherwise the replay runner's default fake answers |
| `tool_result` | `turn, toolCallId, toolName, text` | informational (history recordings only); replay ignores it |

Two ways to produce a recording:

- **Seam (strict)** — `startRecording()` from `src/agent/replay/recorder.ts` while the harness runs
  (tests do this with the faux provider; the app can expose it as a developer switch). Every model
  entry carries a hash, and replay fails with `REPLAY_MISMATCH` when prompts, tools or history differ.
- **History (lenient)** — `pnpm replay:record <session_id> [--project <root>]` rebuilds a recording from
  the app database (`messages`) plus `<project>/.fluxsmith/turns/<n>/subagents/*.json`. Hashes are
  `null`; the replay only checks that the harness consumes the calls in role order without errors.

Sizes: a question turn is a few KB; a full Build turn with subagents is 100 KB–1 MB before gzip.
Recordings never contain credentials (the IPC layer never returns them), but they do contain the
project's schematic text — treat them like the schematic itself.

`sample-question-turn.jsonl` is generated by the replay test with `FLUXSMITH_REPLAY_WRITE_SAMPLE=1`;
it is strict against the current system prompt and tool manifest, so regenerate it after editing either.
